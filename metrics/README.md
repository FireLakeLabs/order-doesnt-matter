# Pull request metrics

`prs.csv` records observations, not performance targets. Blank cells mean no
recorded measurement; zero means a measured count of zero.

`cycle_hours` is elapsed wall time from GitHub `created_at` to `merged_at`, in
hours rounded to two decimals. It includes CI/review/idle time after opening and
excludes implementation before opening. It is **not** task start to completion,
active work time, or evidence of implementation speed. Older date-only rows do
not support recomputing an exact duration.

## PRs 42–47: rework evidence

Filled on 2026-11-14 from GitHub's pull-request and commit API records. For these
six rows, `rework_commits` means non-merge commits with an **author** timestamp
strictly after the PR's creation. This is an explicit post-opening work proxy,
not a claim that review caused the work. Bookkeeping commits count; merge-only
commits do not. Earlier rows retain their historical counting conventions.

Use author dates because PRs 44 and 46 rebased their original commits: their
committer timestamps would incorrectly count pre-opening implementation. Git
allows author dates to be preserved or edited; this proxy cannot establish push
time, private review rounds, or work before the PR opened. GitHub returned no
submitted reviews or issue comments for these six PRs; existing `review_rounds`
values are not corroborated or rewritten here.
