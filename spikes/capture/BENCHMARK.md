# Measurement limits

Claim tested: **bounded source capture is feasible for small pure programs; arbitrary all-station per-keystroke capture is not guaranteed**. This is a feasibility study, not a ranking of production implementations. There is no production renderer/audio path to tune or time.

Environment: Node v24.22.2, npm 11.19.1, 16 logical CPUs. Before the final measurements, `uptime` reported load 9.64/6.49/3.23; background Chrome and headless Chrome processes used substantial CPU. These were other work and were left running. Paired evaluation modes alternate order to distribute noise. Query timings run baseline then AST then runtime and remain susceptible to drift. Exact dependencies are locked. Neither approach is tuned; do not choose an implementation on speed from these numbers.

Each program has one discarded evaluation warmup and five timed evaluations per mode, alternating baseline/AST/runtime and reversed order. Timing includes generated JS compilation in VM and awaiting the program, with real mini/core/tonal construction and recorder work; it excludes worker startup, AST compilation, final root assembly, and queries. Raw samples are in each per-program JSON's `timings`. They were not replaced by a no-op. Core Pattern objects were retained, queried, and compared. Compile measurements are one cold baseline followed by AST, so their apparent relative speed is confounded by warmup and is not a performance conclusion.

The size sweep has five independent workers per size. It fixes output density at four events per cycle and grows a `.gain(.5)` chain from 4 to 64 original calls. All nine cycles are queried for each retained source station, recording 36 × stations returned events. It includes VM timeout setup, Pattern.query, fractional-time/event construction, normalization and snapshot hashing. There are no query failures, incomplete samples, or event/time budget hits in this sweep. Every final result matches baseline. `results/tables.md` reports median and range; `results/size-sweep.json` retains all runs. Summing intermediate work has increasing cost with depth, even with constant final event density.

The prototype alternative intentionally retains only two instances per method name, versus eight per source site for AST. A 64-call gain chain therefore does not ask 64 distinct gain outputs in the runtime case. Its flat query curve is reduced coverage, not evidence of a constant-time equivalent algorithm. Both methods run the same uninstrumented Strudel semantics before recorder overhead and use the same VM/query/event budgets.

`profile.mjs` is a separate unreported diagnostic (eight repetitions, 64-station chain), run using `node --import ./node-setup.mjs --cpu-prof --cpu-prof-dir=results/profile profile.mjs`. The saved CPU profile has 2,109 samples. Hotspots include GC (66 direct samples), core's appLeft query closure (dist line 671), object/control merging (line 506), control value conversion (2157–2170), and fraction.js arithmetic. Repeated construction/allocation along nested queries is a plausible limiter, supported by this profile; it is not a precise allocation breakdown. The profiler's wall time is not included in reported results.

Errors are first-class results: worker errors, evaluation errors, per-query errors/timeouts, event and instance caps all survive in JSON. “Equals baseline” can describe two matching failures; only `fullyChecked` completed all nine cycles. Function-valued event/context behavior remains opaque even with complete projected equality. Prototype and AST source-inspection probes intentionally fail equality. Impure seed 17 intentionally changes after extra observations. These cases are retained rather than omitted as fast results.

A persistent worker, debouncing, visibility-based sampling and caching may reduce interactive latency; this is reasoned, not measured. No keystroke, browser scheduling, rendering or audible path was measured. Background load and differences in retained coverage make a speed winner inconclusive. All times are bounded costs of this particular harness, not universal Strudel limits.
